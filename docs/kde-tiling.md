# KDE Window Tiling (Plasma 6 / KWin 6)

## Two layers of tiling

### 1. Quick tiling (always on, no setup)
Snap windows fast:

- `Meta+←` / `Meta+→` tile to left/right half
- `Meta+↑` maximize, `Meta+↓` restore / bottom half
- Or drag a window to the left/right/top edge of the screen
- **Adjust the split ratio:** drag the divider between two quick-tiled windows; the neighbour resizes with it

### 2. Custom tiles (the tiling manager)
- Press `Meta+T` to open the **Tiles Editor** overlay
- Draw the layout: split tiles horizontally/vertically, resize by dragging edges; nested splits are allowed (e.g. left column + two stacked on the right)
- **Place windows into tiles:** grab the titlebar, hold `Shift`, and drag — the tile zones highlight; drop onto one
- **Resize in use:** drag the border between two tiled windows; adjacent tiles grow/shrink together

## Important behaviours
- **Tiling is per virtual desktop** (Plasma 6.4+). A layout set up on Desktop 1 is separate from Desktop 2; design each desktop's tiling individually via `Meta+T` while on that desktop.
- **It's inherently manual** — built-in tiling has no global on/off lock. You tile windows by snapping them.
- Quick-tile drags use screen edges; holding `Shift` while dragging targets your **custom** tile zones.

## Settings locations
- **System Settings → Window Management → Window Tiling:** padding slider and the "Edit Tiles…" button (same as `Meta+T`)
- **System Settings → Workspace Behavior → Screen Edges:** enable/disable edge-tile triggering
- **System Settings → Shortcuts → KWin:** reassign `Meta+T` ("Edit Tiles") or any quick-tile binding

## Declarative config (Nix / home-manager)
Built-in tiling config lives in `~/.config/kwinrc`:

```
[Tiling]
padding=8
```

The full layout tree is stored per desktop + screen:

```
[Tiling][<desktopUuid>][<outputUuid>]
tiles={"layoutDirection":"horizontal","tiles":[{"width":0.25},{"width":0.5},{"width":0.25}]}
```

- `desktopUuid` is a **random UUID** generated by KWin (persisted in `kwinrc [Desktops]`).
- `outputUuid` is machine-specific, with a deterministic legacy fallback (UUIDv5 of `name:eisaId:model:serial`).
- If no layout is configured, KWin creates a default horizontal 3-column split (`0.25 / 0.5 / 0.25`).

**Gotcha:** when `kwinrc` is fully managed by home-manager as a read-only Nix-store symlink, KWin cannot persist runtime writes — desktop UUIDs regenerate each login and layout edits from the Tiles Editor reset on rebuild. Only the global `[Tiling] padding` is safely declarable in that setup.

## Troubleshooting
- **`Meta+T` won't open the editor:** the Tiles Editor is a KWin effect — enable it in **System Settings → Window Management → Desktop Effects** (`tileseditorEnabled` in `kwinrc [Plugins]`).
- **Layout resets after rebuild:** expected when `kwinrc` is Nix-managed (read-only); only `padding` persists. Redesign with `Meta+T` per session, or make `kwinrc` writable and seed the layout at login (query desktop/output UUIDs at runtime via `qdbus6` + `kwriteconfig6`).
- **Padding stuck at default:** ensure the rebuild completed and re-login (KWin reads padding at startup).
